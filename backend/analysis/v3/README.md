# 第三轮：先改规则，再比较提示词

2026-09-09。本轮四步已实现并实际验证：评判规则调整、先提取亲历与变化、再判断事件关系、局部失败保留其他内容，最后固定同一模型比较两份提取提示词。旧实验保留，现有API、Docker运行服务和前端契约均未改。

## 已改变的行为

- unknowns允许空、缺省；可选说明或额外描述不再让证据失败。
- 原文细分到带上下文的分句编号，程序取回原文，不由模型手抄或生成摘要。先识别谁的经历、事实或意愿，再判断关系。
- 坏引用只拒绝对应条目；模态含糊的条目留在待核对区，其他有效条目保留。关系服务失败、不成立或互相矛盾时，事实列表继续保留。
- 默认不要求全文分类、不要求把每个事实塞入一个完整经历。没有充分事件边界则关系待定，不能把未连接的条目宣称为独立经历。
- 程序通过只是引用与结构成立，并非语义认证。所有条目仍为evidence_linked_unverified，confirmedEpisodes为空，未接入确定展示。

“背调开始，希望通过”已用自动测试验证能分开保留事实与愿望；这不代表任意复句都能正确拆解。模型若又把事实和愿望合成同条，仍可能整条进入待核对区，原文不丢失。

## 比较方法

6例旧回归，4例本轮新验证，共10例。每例运行A、B各一次，顺序交替。同一模型deepseek-v4-flash、同一规则代码、同一关系提示词，唯一自变量是提取提示词。协议、输入、规则、两份提示词和脚本在调用前冻结；未根据结果修改后冒充原成绩。

A为常规提取要求；B强调先判断亲历与模态，再提取具体变化。人工核对由本助手逐项对照原文和上下文完成，无招募人员。材料此前可见，非盲测；单次小样本不说明统计显著性或稳定性。

## 实测结果

| 指标 | 提示词A | 提示词B |
|---|---:|---:|
| 程序保留条目 | 56 | 63 |
| 核对有原文支持的条目 | 47 | 57 |
| 其中与本轮目标相关、有用的条目 | 37 | 48 |
| 分类不受支持 / 仍含混 | 7 / 2 | 3 / 3 |
| 至少有一条有用内容的案例 | 8/10 | 7/10 |
| 新验证集中至少有一条有用内容 | 4/4 | 3/4 |
| 两篇纯建议未当作者经历保留 | 2/2 | 2/2 |
| 程序保留的关系 | 21 | 40 |
| 核对错误 / 含混的关系 | 3 / 8 | 2 / 2 |

“有用”是本次依据原文的人工判断，逐项理由留档。事实有用不代表事件划分正确；保留更多不等于覆盖更完整。不能拿本轮局部有用条目数与上轮“整篇通过0例”直接比较并声称准确率大幅提高，评价粒度已经不同。

例子：

- H02-05：B保留旧offer与两年后新求职，正确分开对应关系；A误把作者的offer两条分成other而排除。这是漏失，不是正确保守。
- H02-10、H03-06：两种提示词都未将建议保留为作者事实。
- H01-01：A仍把两份不同工作面试连接为同一事件；B把“面试结果：”标题当作一条已发生事实。
- H03-02：A仍把未来毕业和辞职后预测标成occurred；B的母亲经历被当作者变化。两者都不应自动认证。
- H04-08：B保留备考、考试、复试和拟录取等进展；A选出一些只有日期的片段，不能算有效变化。
- H01-04：A取到作者自己每天刷新岗位的习惯；B只留下招聘年限和不完整背景句，漏了关键自述。因此B有用条目更多，却少覆盖一个案例，不能断言全方面更好。

## 测试、剩余问题和使用边界

33组离线测试通过，新增8组覆盖：空未知项、实际/愿望分句、局部坏引用、建议与示例、错误关系、矛盾关系、下游失败保留事实、网络与JSON错误分开记录。

关系判断仍有语义错误。模型也会选到标题、只有日期的片段或漏掉关键信息。modal关键词仍可能误伤合法行动，例如“选目标院校”；有事实和愿望的同一条目仍会整体待核对。此次保留这些问题的冻结结果，没有通过事后放宽规则制造胜出。

结论：程序“不必要地全篇拒绝”的问题已有实质改善，现在能保留可核对的局部内容；自动语义可靠性仍未达标。B可作为进一步研究候选，但本次不足以直接替换到自动展示。产品继续使用原文候选与已有核验案例。
