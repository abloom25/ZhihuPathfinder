# 编号引用与两阶段分析：第二轮

本轮按要求实现并验证一次。旧版analysis文件保留；新实现位于本目录；现有后端API和前端契约未改，自动拆分仍未接前端。

## 实现

程序将真实换行及字面反斜线n分段，再给段内句子编号，保留精确文本和起止位置。模型只引用编号，程序取回原文。

第一阶段只区分经历。每个原文单元必须归属一段经历、排除或待定，不能重复归属、悄悄遗漏。第二阶段每次只看到本段原文，再判断行动、已发生变化、条件/愿望和结果。引用另一段的编号会被拒绝，即使引文确实在全文里。

失败保留原文；机械通过仍是待核对，confirmedEpisodes恒为空。若第一阶段已错误合并两件事，第二阶段的隔离无法自动修复该错误。

## 冻结标准与实测

6个旧案例回归，另选6个未用于本轮修正的验证案例。判定依据、实现、提示词和输入哈希均在调用前冻结；未根据结果修改后重算。历史材料此前可见，不是盲测。

预设推进门槛：机械通过的输出无语义错误；9个亲历案例至少6个有用，其中验证集5个亲历案例至少3个有用；3个非亲历案例正确识别。这只是实验门槛，不代表生产安全保证。

| 指标 | 实际结果 |
|---|---|
| 自动测试 | 25组通过，新增编号、归属、跨经历结果、条件措辞及失败回退检查 |
| 真实调用 | 12条材料、22次模型请求；失败不自动重试 |

| 完整有用输出 | 0/12；非亲历正确识别0/3；拦截或服务失败不算识别成功 |
| 推进门槛 | 未通过 |

回归集：H01-01分两份工作方向正确，但unknowns为空被拒；H02-05把等待和获得旧offer拆开；H02-10把读题分析当经历；H03-02把同一倒计时拆开；H03-06把建议当经历；H04-10过拆读研阶段且重复分配单元。

验证集：H01-03一段却声称multiple_supported，且unknowns为空；H01-06合并两个不同机会，杭州未选中结果的范围不清；H02-01把背调拆开；H02-09、H03-05调用/解析失败，日志无法进一步区分原因；H04-09分三段在预设容许范围，但unknowns为空被拒。

## 不混淆的结论

- 编号引用解决了本轮手抄引文问题，但没有证明语义正确。
- 校验本身有过严之处：强制unknowns非空并非必要；事实和愿望同句时整句拦截会误伤事实。不能把这些拒绝都归咎于模型。本轮保留冻结版本，没有放宽规则后冒用原验证集成绩。
- 分组仍会过拆、合并不同机会或把建议当亲历，且可能机械通过。这是不能接自动展示的决定性原因。
- 没有任何确定输出，因此不能用“没展示错误计划结果”证明这类风险已解决。

单例耗时约1.4–10.5秒。成功响应报告token合计21042；失败请求usage未知，不据此计算账单或延迟保证。
