# 《后来呢？》产品说明

> 用知乎上的经历作为参照，让人在看见别人的后来之前先留下自己的判断；看过之后再回看、修正，并把自己愿意分享的变化留给下一位。

## 1. 给谁用、什么情况下用

正在等一个结果的人——等 offer 审批、等面试结果、等体检通知。典型场景是"hr 说在走流程"之后的那一周：反复搜别人的经历找参照，焦虑但没有记录，事后说不清自己当时怎么想的。

## 2. 用户如何完成一次核心体验

1. 进入关卡「等消息的这一周」，面对具体处境：这一周我打算怎么办（暂按原计划等待 / 先了解进展 / 继续推进其他机会，可多选，可自定义做法）
2. **先留下自己的选择和理由（原话）**——揭晓时刻冻结，此后不可改写
3. 揭晓：查看不同人的"后来"——知乎真实经历卡片，每条引文逐字来自原文，标注作者与来源链接
4. 卡片同时给出 conditionDifferences（不同人的条件差异，避免误读为同一个人的平行人生）与 unknowns（哪些后续未知，页面不悄悄补成确定结论）
5. 留下现在的想法（可改变倾向、可补充理由）——与起初的判断**并排保存**
6. 记录保存在本设备，可跨时间追加变化（演示中标注为演示数据）
7. 自愿把一部分分享给下一位：内容先存本机、凭据本机持有，创建后可随时撤回，撤回后链接不可读

## 3. 相对"直接阅读"和"普通笔记"新增了什么

- **相对直接刷知乎**：先记录再看——用户带着自己的判断去读别人的后来，而不是被评论区情绪推着走；每条经历保留不确定性边界，不提供"照抄就赢"的幻觉
- **相对普通笔记**：记录结构是"起初判断 → 看过之后 → 后来追加"三段并排，且知乎来源（链接＋摘录）与记录绑定保存，回看时能解释"我当时为什么这么想、依据是哪条经历"
- **相对两者**：自愿分享机制把"读过的经历"变成"留给下一位的参照"，分享需明确同意、可撤回

## 4. 知乎开放能力在哪里发挥作用

- **知乎搜索 API**（`zhihu_search`，Bearer＋秒级时间戳鉴权）：用户输入处境关键词拉取真实经历候选
- **合规使用**：应用层 5 分钟缓存＋单飞节流＋最小间隔去重（官方要求"有额度限制的能力应缓存去重"）；上游 URL 消毒（仅 https＋知乎域、剥离 UTM 溯源参数与凭据）；候选标注"未经核对、可能包含多次经历"
- **内容纪律**：演示所用全部材料登记于 `backend/contract/素材来源.json`（来源 URL＋原文摘要 sha256＋核对范围）；首页三条经历已核对原页，关卡卡片引文已逐字核对（一条因配额待补，页面保留 unknowns 标注）

## 5. 哪些能力已验证、哪些仍是实验

**已验证**（证据见 `audit/REPORT.md` 与验收记录）：
- 核心七步流程可操作；记录并发安全（跨标签锁、版本冲突拒绝覆盖、写入失败不静默）
- 分享创建/同凭据幂等重试/撤回后不可读；容器重启后分享仍在（docker 实测）
- 真实知乎搜索端到端（live 200、10 条真实候选、UTM 剥离、缓存命中）
- 两轮对抗＋混沌测试：约 4400 条断言零违例（含 SSRF 消毒、原型污染、并发原子性、悬挂上游看门狗、栈安全、精确边界）
- 10 项缺陷已修复并带回归钉住（PR #2 已合并）

**实验性（页面如实标注）**：真实搜索入口、故事库入口、问津路由为探索功能；跨时间追加在演示中标为演示数据；长期留存未验证。
