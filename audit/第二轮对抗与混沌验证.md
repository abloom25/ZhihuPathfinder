# 第二轮对抗与混沌验证

日期：2026-09-14。PR：https://github.com/abloom25/ZhihuPathfinder/pull/1 。本轮是在第一轮修复提交 9317d0c 之后继续检查；第一轮说明中的 47/20 测试计数是历史记录，本轮为 52/22。

## 新增发现与修复

1. **损坏但可解析的分享存储未被拒绝。** 原读取逻辑只确认顶层数组，`[{}]` 也返回成功；公开转换用排除 tokenHash 的方式，会把其他未知字段保留下来。现在逐条校验完整记录或撤回墓碑的字段、类型、ID、凭据摘要、来源及唯一性；任一坏记录令读写返回 503，保持原文件字节不变。公开字段另用白名单输出。此问题由本地磁盘故障注入复现，不代表发现外部用户能任意写入服务器文件。
2. **搜索 mode 错误类型通过校验。** 原 `String(mode)` 使 `['live']` 或多层数组被误认成合法模式。现在先验证字符串类型，再匹配枚举。
3. **不同查询的成功响应会被接受。** 返回结构正确但 query 不同，可能把其他问题的材料当本次结果。现在与本次输入的 trim 后查询核对，不匹配报告 BAD_RESPONSE。

红基线：新建的 6 项检查中 3 通过、3 失败，见 round2-evidence/red.log。修复后新增及已有测试均通过，没有删除失败断言。

## 新增测试

- 768 组分享输入：seed 20260914、42、9001，每组 256 例。`variadicBody(...args)` 的参数数量在 1–7 间变化，参数为递归数组／对象／基本类型，嵌套分支数 0–4，深度上限 6、节点预算 80。逐例断言 400 且原库字节不变，保留合法请求作正对照。失败信息含 seed 与 case 编号；不是无限递归。
- 128 个不同 ID 同时发布，必须全部持久化；32 次交错撤回与重试后，目标保持撤回，POST 返回 409，其他记录不丢失。
- 临时文件路径不可写：让 .tmp 路径变成目录，发布返回 503，原数据库逐字不变；移除故障后同一请求成功。这是临时文件写入失败，未模拟硬件断电或 rename 中途故障。
- 可解析坏库：空对象、标量、未知字段、重复 ID、坏 tokenHash；GET、POST、DELETE 全部拒绝，不向响应泄露注入字段，不修改原始数据。
- 真实本地 HTTP 上游发送响应头后卡住 body：100ms 测试超时返回 504；下一次搜索成功，证明这条失败路径释放了服务端并发门闩。
- 第一轮已有的两个随机种子对抗测试再次通过，共 1024 次查询形状测试，另外包含坏备份和取消请求检查。

## 结果与测量范围

- 后端 **52/52**，前端 **22/22**，两组独立对抗测试各 **8/8**。
- 构建通过；三项保护机制消融 **3/3** 检出；完整步骤退出码见 round2-evidence/run-summary.json。
- 取消请求观察：6000 次，外部 abort 监听净留存为 0。
- 新增真实 HTTP 缓存轮换：960 次搜索，缓存上限 100 条，6 个批次，每批 160 个不同查询，每批后主动 GC。heapUsed 为 10.61、10.76、10.91、9.91、10.02、10.00 MB；没有随请求数持续增长。
- RSS 从约 92.7 MB 增至 121.3 MB，末两个批次变化约 0.1 MB。RSS 增长不能仅凭 heap 稳定解释为无风险；本轮是短时单进程测量，没有做长时间运行、浏览器堆快照或多实例共享文件测试，不能宣称没有内存泄漏。
- JSON 文件存储仍只适用于单个写入进程。并发测试是同一 Node 实例，不代表多实例部署安全。

## 复跑

安装依赖后，在隔离副本的根目录执行：

```sh
npm test
AUDIT_RESULTS=audit/round2-recheck node audit/run.mjs
AUDIT_RESULTS=audit/round2-recheck node --expose-gc audit/deep-memory-probe.mjs
```

只使用合成数据、本机临时目录和本机 HTTP 服务；没有真实知乎请求、用户数据或密钥。故障目录均在 finally 清理。现有后端测试会刷新两个验证 JSON 的时间字段，注意将结果作为证据而不是业务修改提交。
